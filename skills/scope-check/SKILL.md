# Skill: разбор scope багбаунти-программы

Используй, когда пользователь приносит программу (HackerOne/Bugcrowd/Intigriti/Own
программу) и спрашивает, что можно тестировать, или перед началом работы над целью.
Триггер: «входит ли X в scope», «разбери программу», «куда тут копать».

## Порядок разбора policy

1. **Ассеты, а не домены.** Выпиши всё из In-scope: домены, IP-рейнджи, API,
   мобильные приложения,Play Store/TestFlight ссылки. Wildcard `*.example.com`
   — не то же, что `example.com`: субдомены третьего уровня могут быть out.
2. **Exclusions читай дважды.** Out-of-scope обычно длиннее in-scope: staging,
   маркетинговые сайты, сторонние сервисы (Zendesk, Intercom — не их баги),
   "any subdomain not listed". Ведение своей цели мимо policy = не гарантированная
   выплата и возможный бан.
3. **Severity-таблицу**, если есть: что программа считает P1...P4 — это их
   словарь, твоя оценка должна совпадать, иначе будут споры.
4. **Special rules**: автоматический скан запрещён? Только определённые типы
   багов (некоторые программы берут только auth-bypass/RCE)? Bounty-таблица
   с нулями для low? Это определяет, стоит ли время тратить.
5. **Safe harbor** — есть ли упоминание legal-safe-harbor. Нет — аккуратнее
   с границами, особенно с rate limiting.

## Что проверить по цели перед тестом

- Жив ли ассет (dead scope — трата времени)
- Не принадлежит ли «забытый» поддомен стороннему сервису (тогда не их баг)
- Wildcard DNS: если `*.example.com` резолвится на один IP — скорее всего
  виртуальный хостинг, найденные там чужие сайты не засчитываются
- Версия приложения в магазине vs последняя (старые версии часто out)

## Красные флаги программы (личный фильтр)

- Bounty table начинается с P3 — на P1/P2 «по усмотрению»
- Нет safe harbor
- «No automated scanning» вместе с «we own all findings during triage»
- Scope из одного маркетингового сайта

## Выход

Короткая сводка: in-scope список, главные exclusions, 2-3 направления с
наибольшей вероятностью находки (по типам ассетов), спорные места policy —
если есть неоднозначность, фиксируй её письменно ДО первого запроса.
